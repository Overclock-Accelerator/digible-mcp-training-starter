MCP Training · Part 05

MCPs for everyone

The same server a developer wires into an agent, reached by someone who has never opened a terminal. This is the payoff for everything in parts 00 through 04 — and the reason it was worth moving off stdio.

~10 min live Claude Desktop 1.40609.0 Claude Code 2.1.251 Verified 2026-08-31

01 Why this matters

The repo README made a three-part argument: centralize, monitor, democratize. Parts 01 and 02 delivered the first two. This is the third, and it is the one that changes who gets to participate.

Here is the claim, from the README:

"An MCP server is not a Python import, so reaching it does not require being able to write Python. The same server a developer wires into an agent, a non-engineer reaches from Claude Desktop."

Take that literally, because it is literally true. In 02, using the Spelling Bee solver required: a Python 3.10+ install, a virtualenv, six pinned packages, an ANTHROPIC_API_KEY copied into .env.local, and the knowledge that agent.invoke() will fail where ainvoke works. That is not a high bar for an engineer. It is an absolute bar for everyone else — not "difficult", but "no".

After part 04, the same solver is at a URL. The requirements collapse to: have Claude Desktop, paste a URL once.

Before (parts 00–02)After (part 04)

To use it you needPython, a venv, pinned deps, a key in .env.localClaude Desktop

Who maintains itEveryone, separately, driftingOne repo, one deploy

The point

Nothing about the server changed to make this true. The solver bodies are still byte-identical to shared/solvers_reference.py, exactly as they have been since 00. What changed is the seam — and moving the seam to HTTP moved the audience from "engineers" to "colleagues".

02 First: is the server open?

Before any config, know which of two worlds you are in — because it changes what attendees will see when they click Connect.

Verified by direct request, 2026-08-31

As of the day this page was written, https://mcp-puzzlemaster.fastmcp.app/mcp has Horizon authentication turned on. An unauthenticated request gets:

HTTP/2 401
www-authenticate: Bearer realm="FastMCP",
  resource_metadata="https://mcp-puzzlemaster.fastmcp.app/.well-known/oauth-protected-resource"

{"error":"invalid_request","error_description":"Bearer token required"}

That is not an error. That is a server correctly refusing an anonymous caller and politely telling it where to go and ask permission. Follow that pointer and the server advertises a full OAuth 2.1 setup: authorization code flow with PKCE, and dynamic client registration — meaning a client can register itself, on the spot, with no one issuing it credentials by hand.

That last detail is why this works for non-engineers at all. Nobody has to generate a token. The client and the server negotiate it between themselves, and the human just sees a sign-in window.

If auth is…The attendee experience is…
ON (as of writing)Paste the URL, click Connect, a Horizon sign-in window opens. They need an account in the Overclock Accelerator Horizon org.
OFF (public server)Paste the URL, click Connect, done. No sign-in, no account, no token.
Decide this before the session

Overclock Accelerator is on the Horizon PRO plan, which allows both public servers and org member invites. So there are two workable options:

  1. Turn Horizon auth off for the session. Simplest by a wide margin — the config drops to a bare URL and nobody signs in to anything. It is a read-only puzzle solver over a public dictionary, so the exposure is a stranger solving a crossword. Turn it back on afterwards.
  2. Invite attendees to the org ahead of time. More faithful to how you would really ship this, but it is a room of people doing an email round-trip during a ten-minute slot.

Everything below works either way. Where it matters, both cases are covered.

03 Connecting Claude Desktop

There are two different mechanisms in Claude Desktop that both look like "adding an MCP server", and knowing which is which will save you the twenty minutes almost everyone loses here.

Verified: Claude Desktop 1.40609.0 on macOS (Darwin 25.6.0), 2026-08-31

Not verified by clicking: menu labels below come from Anthropic's help centre and Horizon's documentation, not from a walkthrough of this build. Trust the screen over this page.

Read this before you touch any config

Claude Desktop does not read .env.local. It has never read it and it never will.

The repo's Python agents get their key from .env.local at the repo root, loaded by shared/envloader.py. That is a convention that exists inside this repository, for this repository's Python. Claude Desktop is a separate application that knows nothing about your repo, was not launched from it, and has no idea the file exists.

Claude Desktop reads exactly one file: claude_desktop_config.json, in its own application-support directory. If this server needs auth, the credential goes there — or, better, through the OAuth flow, where you never handle a credential at all.

People conflate these constantly, and the reason is understandable: both are "the file where the key goes", and both involve Claude. But they serve different programs on different sides of a boundary.

.env.localclaude_desktop_config.json

Lives atThe repo rootClaude's app-support directory, outside the repo
Loaded byshared/envloader.py, at importClaude Desktop, at launch

The good news

You do not need an ANTHROPIC_API_KEY for anything on this page. That key exists so the repo's Python agents can call a model. Claude Desktop already is the model, with your own subscription behind it. An attendee following this page needs no key, no .env.local, and no repo — which is precisely the point of Part 05.

Path A — Connectors Recommended

A UI flow. Paste a URL, click Connect, sign in if asked. This is the one that handles OAuth, which is exactly what our server requires. No file editing, no restart.

Use this for non-engineers. Use this in the live demo.

Path B — claude_desktop_config.json For the config-curious

A JSON file on disk. Historically this was stdio-only — for launching local server processes. Support for remote URLs has been arriving, and Horizon publishes a config shape for it, but the two authoritative sources disagree about whether it works. Details and both shapes below.

Path C — mcp-remote bridge Fallback

Wrap the remote server as a local stdio process that does the OAuth dance for you. Needs Node. Ugly, and it has always worked.

Path A — Add a custom connector

  1. Open connector settings

    In Claude Desktop, go to Settings → Connectors (listed under Customize in some builds).

    On a Team or Enterprise plan, only an Owner can add one, and they do it from Organization settings → Connectors → Add, then hover Custom and choose Web. Everyone else waits for that and picks up at step 4.

  2. Add custom connector

    Click “+”, then “Add custom connector”.

  3. Paste the name and URL

    FieldValue
    NamePuzzleMaster
    Remote MCP server URLhttps://mcp-puzzlemaster.fastmcp.app/mcp

    There is an Advanced settings section offering an OAuth Client ID and Client Secret. Leave both empty. Our server supports dynamic client registration, so Claude registers itself. Those fields exist for servers that require pre-issued credentials.

    Click Add.

  4. Connect

    Find the connector in the list — it carries a Custom label — and click Connect.

    If Horizon auth is on, a browser window opens for sign-in. Approve it, and the window hands the credential back to Claude. If auth is off, it connects immediately.

  5. Turn it on in a conversation

    The step everyone misses

    Adding a connector does not enable it in your chats. In a conversation, click the “+” at the lower left, choose “Add connectors”, and toggle PuzzleMaster on.

    If someone says "I added it and nothing happened", it is this, roughly nine times out of ten.

Path B — the config file

You asked for the exact config, so here it is with the caveat attached, because the caveat is the useful part.

Where the file lives

OSPath
macOS~/Library/Application Support/Claude/claude_desktop_config.json
Windows%APPDATA%\Claude\claude_desktop_config.json
expands to C:\Users\<you>\AppData\Roaming\Claude\claude_desktop_config.json

Do not make anyone type those paths. Both are reachable from inside the app: Settings → Developer → Edit Config, which opens the file in your editor and creates it if it does not exist.

The remote-server shape, as Horizon documents it

claude_desktop_config.json — auth OFF (public server)

{
  "mcpServers": {
    "puzzlemaster": {
      "url": "https://mcp-puzzlemaster.fastmcp.app/mcp",
      "transport": "http"
    }
  }
}

claude_desktop_config.json — auth ON, with a Horizon API key

{
  "mcpServers": {
    "puzzlemaster": {
      "url": "https://mcp-puzzlemaster.fastmcp.app/mcp",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer fmcp_YOUR_HORIZON_API_KEY_HERE"
      }
    }
  }
}
Two honest warnings about Path B

1. The sources disagree about whether this works. Horizon's documentation publishes exactly this shape for Claude Desktop. Anthropic's help centre describes claude_desktop_config.json as a separate mechanism for local servers, and says remote connectors do not use it. There are public bug reports of Claude Desktop reading a URL entry, failing to recognise it as remote, and logging a missing-extension error instead of starting an OAuth flow.

We did not test this shape against build 1.40609.0. If you try it and no tools appear, that is not your JSON — go to Path A.

2. That bearer token is a real secret in a plaintext file. An fmcp_ key grants your Horizon access to anyone who reads that file — and this file gets screen-shared, backed up, and synced. The connector flow in Path A stores its credential properly instead. Prefer it. If you must use a key, treat that file as sensitive, and rotate the key if it is ever shown on a projector.

You must fully quit to reload

Restart, properly

Claude Desktop reads this file at launch only. Closing the window is not quitting.

macOS: Cmd + Q, or Claude → Quit. Not the red dot.
Windows: quit from the system tray, not just the window X.

Connectors added through Path A do not need a restart. This applies only to the config file.

Path C — the mcp-remote bridge

If Path A is unavailable and Path B does nothing, this is the fallback that has worked throughout. It runs a small local process that presents the remote server as a local stdio one and handles the OAuth browser flow itself.

claude_desktop_config.json

{
  "mcpServers": {
    "puzzlemaster": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@latest",
        "https://mcp-puzzlemaster.fastmcp.app/mcp"
      ]
    }
  }
}

Requires Node.js. On first connect it opens a browser to sign in and caches the credential locally. Note that this is a genuine local subprocess — which means, unlike Paths A and B, the connection originates from the laptop rather than from Anthropic's cloud. Occasionally that difference is the thing that makes it work.

04 Verifying it worked

Three checks, cheapest first.

  1. The connector shows as connected

    Settings → Connectors. PuzzleMaster should appear with a Custom label and read as connected rather than offering a Connect button. If the icon is greyed out, it is not connected.

  2. The tools are listed

    In a conversation, click the “+” → Add connectors and toggle PuzzleMaster on. Expanding it should show five tools:

    ToolIn plain language
    solve_spelling_beeFind every valid word for a Spelling Bee puzzle
    solve_crossword_patternFill a pattern like c_o__w_rd
    solve_wordleNarrow Wordle candidates from guesses and colours
    usage_graphShow who has been calling what
    export_resultsDump the audit trail as CSV

    Five tools listed means the handshake succeeded and Claude has read the server's manifest. That is a real end-to-end success signal — you cannot list tools without a working authenticated connection.

  3. Ask it something and watch for the tool call

    The proof is the tool-use indicator in the response. Claude will show that it called PuzzleMaster, and you can expand it to see what it sent and what came back.

    Worth pointing at on the projector

    Expand the tool call and show the room the raw input and output. This is the same JSON that 02's middleware wrote into the audit table, and the same request Horizon's Logs page is recording right now. Three views of one event — it makes the whole architecture click for people who have been taking it on faith.

Warm it first

Horizon scales to zero, so the first request after an idle period pays a cold start — loading the runtime, the dependencies, and 172,823 words of dictionary. Do one throwaway call a minute before you present. Otherwise your opening demo is a spinner.

05 Things to try

In plain language. No syntax, no parameters — the model works out which tool to call and what to put in it. That translation is the demo.

Spelling BeeToday's Spelling Bee letters are V A L I D T Y and the centre letter is V. What words can I make?
CrosswordI need a nine-letter word matching the pattern c_o__w_rd.
WordleI played CRANE and got green, yellow, black, black, black. What could the answer be?
Monitoring — the one non-engineers find surprisingShow me the usage graph grouped by agent.
ExportExport the results and tell me what's in the file.

What to point out while it runs

Nobody typed a parameter. The user said "V A L I D T Y, centre letter V" and the model produced letters="VALIDTY", center="V". The tool is still perfectly rigid — it takes exactly the arguments it always took. The model is doing the translation from human phrasing into that rigid shape. Last session's lesson was that tools make agents deterministic; this is the other half of that trade, and it is the half that lets a non-engineer drive.

The answers are the same ones the Python agent got. Same server, same dictionary, same code path. Not a re-implementation that will drift.

Ask for the usage graph. It reports every call from every source — the Python agents from 02 and the Claude Desktop session you are currently running, side by side in one chart. This is the centralize-and-monitor argument made visible, and it is the moment the room usually gets it.

Say the number out loud

Against the real 2026-08-28 puzzle, our public word list finds 34 words for 171 points. NYT accepted 21 words for 119.

The solver is not broken. It is answering a different question than the editor was — "which letter combinations are in ENABLE1" versus "which words did a human decide belong in today's puzzle". Worth saying to a non-technical audience explicitly: a deterministic tool gives you exactly what you asked for, which is not always what you wanted. Making the tool easy to reach does not make that gap go away. It just puts it in front of more people.

06 The same server in Claude Code

For contrast. Identical server, identical URL, one command instead of a settings panel.

Verified against Claude Code 2.1.251, 2026-08-31 — flags below are from the installed binary's own --help

claude mcp add --scope local --transport http \
  puzzlemaster https://mcp-puzzlemaster.fastmcp.app/mcp

Then, inside Claude Code, type /mcp to complete the interactive sign-in. Check it with:

claude mcp list

Scopes

ScopeWhere it is storedUse when
local (default)This project, just youTrying it out
userAll your projectsYou want it everywhere
project.mcp.json, committedThe whole team should get it on clone

--scope project is the interesting one: it writes .mcp.json into the repository, so the next person to clone gets the server configured without being told it exists. Centralization reaching one step further than the server itself.

If a server needs a static token instead of interactive sign-in

claude mcp add --transport http puzzlemaster \
  https://mcp-puzzlemaster.fastmcp.app/mcp \
  --header "Authorization: Bearer fmcp_YOUR_HORIZON_API_KEY_HERE"

Prefer the interactive flow. A key in a shell command lands in your shell history, and --scope project would commit it. There are also --client-id, --client-secret, and --callback-port flags for servers that require pre-registered OAuth clients; ours does not.

The contrast worth drawing

One is a settings panel, one is a shell command, and they reach the identical endpoint and get the identical five tools. The server does not know or care which one is calling.

That is the whole architectural payoff. You do not maintain a version for engineers and a version for everyone else. You maintain one server, and clients differ only in how a human tells them where it is.

07 What a non-engineer can and cannot do

"Anyone can use it" is not the same as "anyone can do anything with it". Worth being precise, because this is the question a security-minded person in the room is already forming.

CanCannot
Call any of the five tools, in plain languageAdd, change, or remove a tool
See every result, and the raw input/output of each callChange what a tool does with its input
View the usage graph and export the audit CSVReach the Postgres database directly
Combine tools with everything else in the conversationReach anything the server does not expose as a tool
Connect and disconnect the server themselvesDeploy, redeploy, or roll back
See the tool descriptions and parameter schemasSee DATABASE_URL or any environment variable

Where the guardrails actually live

Not in the client. Everything above is enforced on the server side, which is the only place it can be enforced — and there are four distinct layers:

  1. The tool surface. A client can call the tools the server exposes and nothing else. There is no "run arbitrary SQL" tool, so there is no amount of clever prompting that produces one. This is the strongest guarantee on the list, and it is structural — it comes from what you did or did not write in server.py.
  2. Parameter schemas. Each tool declares its parameters and types. FastMCP validates against that schema before your function body runs. Bad input becomes a ToolError, not undefined behaviour.
  3. Horizon's gateway. Authentication, access policy, and per-request logging all happen before your code runs. If auth is on, an unauthenticated caller never reaches your Python at all — as the 401 in section 02 demonstrates.
  4. Secrets never leave the runtime. DATABASE_URL is an encrypted Horizon environment variable injected into the process. It is not in the repo, not in the tool schemas, and not visible to any client. A connected user can read the audit log through usage_graph and export_results — because those tools were deliberately written — but has no path to the database itself.
Carry this forward

Everything a connected user can do is something someone chose to expose. The reason a non-engineer cannot do damage here is not that they lack the skill. It is that the server offers five read-only tools over a public word list.

Expose a tool that writes to production, and "anyone can reach it from Claude Desktop" stops being a democratization story and becomes an access-control problem. The ease of connection is a multiplier on whatever you decided to expose — in both directions. Part 03's authenticated-writes exercise is where that stops being hypothetical.

One honest note on identity

02 was blunt that agent_name is telemetry, not authentication — an ordinary tool parameter the model fills in, which it can get wrong or be made to get wrong. That is still true of that column.

But over HTTP there is now a second, better identity running alongside it: Horizon's gateway attaches a verified actor — a real user or service account — to every request, established before your code runs and entirely outside the model's reach. That is the Depends()-shaped property 02 pointed at: trustworthy because unreachable, rather than trustworthy because nothing gains from lying. Use agent_name to label your own telemetry. Use the gateway's actor when the answer has to hold up.

08 Troubleshooting

The server does not appear at all

  • Did you fully quit Claude Desktop? Config-file changes load at launch only. Cmd + Q on macOS; quit from the system tray on Windows. Closing the window is not enough. This is the single most common cause.
  • Is the JSON valid? One trailing comma silently disables the whole file. Paste it into any JSON validator.
  • Is it under mcpServers? The key is exact, and the file may already contain other servers — add yours alongside them rather than replacing the object.
  • Did you edit the right file? Use Settings → Developer → Edit Config rather than guessing a path.
  • Free plan? Free is limited to one custom connector. If you already have one, this one will not add.
  • Was it Path B? The config-file route for remote URLs is the one whose support is genuinely unclear. Switch to Path A.
  • Did you put something in .env.local and expect Claude Desktop to pick it up? It will not. Different file, different program, different side of the boundary — see the top of section 03.

It connected, but there are no tools in the conversation

  • Almost always: the connector is not enabled in that chat. Click “+” → Add connectors → toggle it on. Adding a connector does not enable it everywhere.
  • Start a new conversation — a chat opened before the connector existed may not pick it up.
  • If the tool list is empty rather than absent, the handshake succeeded but the manifest is empty. That is a server-side problem: check the Horizon build logs for a failed inspection.

Authentication failures

  • 401 / "Bearer token required". Expected when Horizon auth is on and you have not signed in. Use the connector's Connect button and complete the browser flow — do not go hunting for a token first.
  • Signed in but still refused. Your Horizon account is probably not a member of the organization that owns the server. Ask Ahmed for an invite to the Overclock Accelerator org. PRO includes member invites.
  • Worked yesterday, 401 today. The session expired — Horizon's session routing TTL is 24 hours. Disconnect and reconnect the connector to redo the OAuth flow.
  • Pasted an fmcp_ key and it is rejected. Check for a truncated paste, and that the header is exactly Authorization: Bearer fmcp_... with a single space after Bearer.
  • The browser opens and immediately closes with nothing happening. A pop-up blocker or a non-default browser without an active Horizon session. Sign in to horizon.prefect.io in your default browser first, then retry.

Timeouts and slowness

  • The first call is slow, later calls are fast. Cold start. Normal. Warm it before demoing.
  • Everything times out. Custom connectors are reached from Anthropic's cloud, not your laptop — true even though Claude Desktop is running locally. A corporate firewall or VPN restricting outbound traffic will not help, but a server on a private network or localhost genuinely cannot work this way. Ours is public, so this should not bite.
  • A call fails after a long wait. Horizon's request timeout is 170 seconds. Unlikely for a dictionary lookup; possible for a very large export_results.
  • A large export fails. The payload ceiling is 6 MB per response, with no streaming. Ask for a filtered export instead.

Checking whether it is the server or the client

If you have a terminal, this settles it in one command. Reachable-but-refusing looks like this:

curl -sD - -o /dev/null -X POST \
  https://mcp-puzzlemaster.fastmcp.app/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

A 401 with a www-authenticate: Bearer header is good news — the server is up, reachable, and enforcing auth, so the problem is on the client side. A timeout or a 5xx means the problem is the server or the network, and no amount of reconfiguring Claude Desktop will fix it.

Beyond that, the Horizon dashboard's Logs page shows whether the request arrived at all — and if it did, which client sent it and what the gateway did with it. That answers "is it me or is it them" definitively, which is usually the question.

09 Recap

  • Claude Desktop does not read .env.local. That file is for the repo's Python agents. Claude Desktop reads claude_desktop_config.json. You need no API key for anything on this page.
  • Use Settings → Connectors, not the config file. It handles the OAuth flow, which is what this server requires, and needs no restart.
  • The config file lives at ~/Library/Application Support/Claude/claude_desktop_config.json on macOS and %APPDATA%\Claude\claude_desktop_config.json on Windows — reachable from Settings → Developer → Edit Config. Editing it requires a full quit and relaunch.
  • Adding a connector does not enable it in a conversation. "+" → Add connectors → toggle on.
  • Decide the auth question before the session. Turning Horizon auth off for a read-only puzzle solver is the low-friction path.
  • Claude Code reaches the identical endpoint with claude mcp add --transport http. Same server, same tools, different front door.
  • The guardrails are server-side, and everything a user can do is something someone chose to expose. Ease of access multiplies that decision in both directions.
  • Warm the server before you demo.
The argument, closed

Centralize — one implementation, in one repo. Monitor — one place that sees every call, from every client, whether it is a Python agent or a colleague typing a sentence. Democratize — a URL, and no Python required.

The solver bodies have not changed since 00. Only the seam moved. That was the whole point.
